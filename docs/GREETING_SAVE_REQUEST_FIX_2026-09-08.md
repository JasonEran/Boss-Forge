# BOSS 招呼语实际保存请求修复

生产日志三次 `BOSS_GREETING_SAVE_REJECTED`，复现普通 fetch 返回 HTTP 200 / code 121 / 请求不合法。BOSS v11323 官方 833.js、838.js 的请求客户端均为 Axios/XHR，并设置 `with-common-headers: true`；页面已有的公共请求钩子据此附加请求信息。使用同样的 XHR 方式，以已配置岗位的原文实际提交，返回 code 0，独立读回正文保持一致。

现在 GET/POST/读回统一走页面原生 XHR 和公共头钩子，保留岗位精确绑定及正文读回核验。30 秒总请求时限；单请求最长 20 秒。确认保存成功后最多读回 3 次，处理短暂同步延迟，不重复提交保存。明确业务拒绝单独传递 `greeting_save_rejected`；网络或回执不确定不自动重写。

上一版线上 busy 检查使用已配置的相同文案，命中了“不重复写入”分支，证明的是等待与读取；没有覆盖实际 POST。本次增加未配置岗位首次保存、真实 POST 请求方式、表单编码、延迟读回、拒绝及四类不确定响应的回归。

110 文件 / 767 项测试、类型检查通过。前端资产沿用上一版，此次仅修改 Worker、API 与 IPC。

发布：`boss-greeting-xhr-20260908-1918cst`。用户确认报错岗位为亚马逊运营，使用界面默认参考文案验证首次设置：你好，我们正在招聘亚马逊运营。看了你的经历，想邀请你进一步交流这个岗位。

线上首次保存验证完成：亚马逊运营 configured=false → POST 200 → 独立 GET 200 / configured=true，精确岗位 ID、默认参考正文及 greetingId 均读回一致。平台审计已记录配置更新；联系意图仍为 0，没有发送候选人消息。验证平台会话已撤销。HTTPS 健康检查和 Web 通过，服务均健康；上传包及本地诊断临时文件已清理，备份和上一个版本保留。
