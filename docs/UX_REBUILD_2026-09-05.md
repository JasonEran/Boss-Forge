## 用户体验

- 全部页面共用一个工作区：固定导航、统一页头和模块标签；移动端保留可横向滚动的导航。
- 岗位和任务选择按用户会话保存，并写入 URL；任务可以直接打开自己的候选人和联系名单。历史任务不会被最新任务覆盖。
- 候选人工作区整合待审核、已通过、未通过／淘汰、精筛异常和全部名单；支持姓名、经历和技能搜索，以及分页。
- 审核支持上一位／下一位、提交后自动继续、固定操作栏。未提交的备注不会跨人带入；快速切换时旧请求不会显示成新候选人的信息。
- 岗位规则表单加宽并固定保存按钮，保留所有筛选条件和原有规则版本能力。
- 任务显示创建时间、真实处理进度和直接查看名单的入口；定时计划完整显示。
- 保留联系动作区分、消息模板、招聘流程、团队设置、运营分析、登录与审计能力。
- 修复后台轮询覆盖操作错误、刷新选择错位、旧详情回填、退出仅清本地状态的问题。

## 简历定位

原流程在推荐来源且已有 BOSS 卡片标识的首次精筛中，跳过恢复岗位列表。共享浏览器被其他采集或联系操作切换岗位后，会在错误列表查找旧卡片；列表刷新后的卡片标识变化也无法在首次尝试恢复。

现在每次精筛都先恢复任务的推荐／搜索上下文，再使用原始标识或唯一姓名与稳定卡片指纹定位当前卡片。正常循环优先处理可执行的简历任务，再采集新的岗位。单次领取仍只发起一次简历预览。

历史 `source_expired`／`target_missing` 允许人工重新定位并精筛，任务级重试和候选人入口保持一致。缺失目标仍不自动循环重试；真正消失的卡片或不一致的同名人不会被替代读取。

## 运行状态

服务器更新前，BOSS 登录状态文件停留在一次 `Execution context was destroyed` 错误，而 Worker 心跳仍在更新。修复包含：

- 页面导航导致探测上下文失效时，重新获取页面并做最多三次只读探测；真正登录失效或其他连接错误仍返回实际状态。
- 监督进程直接启动 Node Worker，让停止信号到达实际工作进程，避免包管理器中间进程导致状态与执行脱节。
