当前产品结论是：**基本够用。** 普通 HR 可以完成岗位、规则、任务、逐任务候选人、人工审核、岗位招呼语预览、联系正文预览和分别确认两个动作；任务取消、重试和失败恢复也有清楚动作。真实传输和安全门禁已经部署，但全局/部门控制仍 safe-off，首次真实写入尚未验收，因此不能把“runtime 已开启”写成“真实发送已通过”。

生产浏览器登录目录保持持久化，worker 重启后会话仍为 `authenticated`。三简历验收先以 `collection-only` 采集 15 名新候选人且 0 次打开简历，再以 `resume-only` 严格执行 3/3 次查看并退出 0，没有第四次。结果为 1 份 `target_missing` 安全失败、2 份成功 OCR 并按规则判为不符合；完整证据见 [生产三简历全路径验收](THREE_RESUME_ACCEPTANCE_2026-09-04.md)。

部署浏览器复验曾发现一个 P0：旧构建把 `NEXT_PUBLIC_CONTROL_API_URL=http://127.0.0.1:3100` 烘焙进前端，非本机 Safari 在 HTTPS 页面会请求访问者自己的 loopback，表现为 `Load failed`。最终 release 已部署同源回退与镜像构建参数预检；Safari 刷新旧会话后直接进入 Dashboard，岗位、任务、候选人、联系、联系安全设置、运营、设置和审计页面均成功加载，没有再出现 `Load failed`。

首次复核时发现的“隐式先打招呼再发正文、没有权威回执”问题已被当前 release 取代：现在 `greet` 与 `message` 是两个独立动作，分别预览、分别签名、分别建意图和分别取得 transport 证据；签名精确绑定候选人、BOSS 发件账号、岗位、任务、稳定 locator 与正文。首次真实 canary 仍是独立验收项；canary 前必须把具体动作、候选人、发件账号和完整正文展示给用户，并取得对该组合与正文的精确许可。历史阻断与后续状态见 [真实消息发送开启复核](CONTACT_SEND_ENABLEMENT_2026-09-04.md)。
