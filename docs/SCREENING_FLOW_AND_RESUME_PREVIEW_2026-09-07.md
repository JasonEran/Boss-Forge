# BOSS 官方筛选 + 补充核验、完整简历预览

> **历史记录 · 2026-09-07**：下文保留当时的版本、验证和限制，不代表当前生产状态。现行说明见[文档索引](README.md)、[当前状态](CURRENT_STATUS.md)与[运维手册](OPERATIONS_RUNBOOK.md)。

本次将新规则的职责拆开，并把完整截图接入候选人审核。

- 第一步直接设置 BOSS 官方学历、经验、院校、专业、关键词、活跃度等选项；新规则不再要求 HR 理解自动、自定义、不使用三种模式。
- 第二步配置 BOSS 不能直接确定的证书、具体技能、毕业年份、简历原文等补充要求；不重复放置学历、工作年限、BOSS 院校标签。语义观察仍保留原来的试运行含义，不悄悄升级为淘汰条件。
- 新规则带 `screeningFlow: boss_then_resume`。只有任务实际应用的官方条件与当前规则一致时，才记录官方筛选通过；历史样本重放不会假定新条件已经应用。允许只使用非空官方条件，同时继续读取原始简历供 HR 审核。
- 旧规则按旧语义读取和执行，避免保存或重放时改变旧任务结论。新规则必须绑定 BOSS 岗位，使用对应推荐名单；立即任务与定时任务都拒绝混用搜索来源。

## 完整截图和审核

截图先滚动到正文底部，等待延迟内容稳定，再展开嵌套滚动区域。每段 1600 CSS 像素，相邻段保留 80 像素重叠，逐段滚动到可绘制区域截图，避免跨域 iframe 在视口外绘制为空白。不会把浏览器视口撑到整份简历高度。

每段检查 PNG 尺寸和实际像素；确认覆盖到正文底部、截图期间正文没有继续变化后，才发布完整性清单。失败会删除本次分段，返回 `content_incomplete` 并按现有有限重试机制处理，不使用半份简历产生判断。异常超过 80,000 像素或持续加载也明确失败，不静默截断。

截图前展开普通 DOM / SVG 的“查看全部”。生产腾讯 OCR 路径还逐段识别 BOSS 的 WASM 画布，通过按钮的实际坐标展开个人优势等折叠内容，然后重新截图、再次检查，最多 12 轮；不会点击 VIP 分析或联系操作。最终完整版本的 OCR 与截图哈希绑定复用，避免重复识别。

腾讯 OCR 和已有百度 OCR 路径均读取全部分段。任何一段识别失败都会终止本次 OCR，不把之前几段当成全部正文。分段边界保留少量重复文字，避免误删有效内容。

确认展开和完整性后，截图在后续识别与规则判断前保存到候选人记录，后续 OCR 失败时 HR 仍可预览；画布展开检查本身失败时不会发布未确认完整的截图。审核详情增加简历预览、加载进度、分段序号和放大/适宽；按候选人清理浏览器图片资源，截图更新时拒绝混用旧段与新段。历史单张截图可预览，但标记为未确认是否截全。

API 复用现有用户和岗位访问范围；图片通过认证请求读取，不返回服务器路径。API 容器只读挂载已有 BOSS 截图卷，不修改登录卷或数据库结构。
