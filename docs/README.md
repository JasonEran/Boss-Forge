## 维护规则

1. 当前事实写入 `CURRENT_STATUS.md`，R1–R6 交付记录和后续上线工作写入 `ROADMAP.md`。
2. 产品需求与当前状态必须按已验证代码同步更新。
3. API、表名、状态和环境变量以代码为准；修改代码时同步对应文档。
4. 测试数量只在重新执行全量测试后更新。
5. 真实联系状态必须区分仓库能力门、磁盘配置、运行容器环境、Worker 进程、控制记录和是否实测；生产结论必须引用对应 release 与现场复验。
6. 已执行的历史数据库迁移不能重写；废弃字段通过新迁移处理。
7. 大模型能力必须注明“已接入”或“规划中”，并记录模型、提示词、语义目录和评分标准版本；当前只允许 off/shadow，不得把 shadow 指标写成 active 验收。
