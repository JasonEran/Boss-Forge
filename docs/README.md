## 维护规则

1. 每次行为变更更新对应现行手册；运行发布与现场验证写入 `CURRENT_STATUS.md`，不要在多个入口复制易过期的统计。
2. 明确区分：代码已实现、隔离测试通过、应用已部署、真实业务观察通过。缺一项不能靠另一项推断。
3. 运行数值必须带时间和环境；测试数量必须带日期、执行环境和关联记录。本次未执行的测试不得写成通过。
4. 新增历史报告时加入 `HISTORY.md`，保留旧结论，使用补充说明纠错，不把历史结果改写成新验收。
5. 命令标明本地还是服务器，示例使用占位符，不写密码、会话令牌、Cookie、真实简历正文。
6. 相对链接指向仓库文件。提交前检查目标文件、章节锚点、npm scripts、配置名及 `git diff --check`。
7. 文档提交可以领先生产应用版本。只有运行代码变更才要求对应应用发布，不为文档重启正在招聘的服务。
