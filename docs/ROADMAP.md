## 已交付

| 领域 | 现有能力 | 主要边界 |
| --- | --- | --- |
| 组织权限 | 部门、四角色、岗位成员、会话与审计 | 单部署内部团队定位 |
| 岗位与规则 | 完整同步、ID绑定、官方筛选、版本发布、证据 | 换账号后不自动迁移配置 |
| 任务与计划 | 即时/周期、串行分波、目标计数、日上限 | 候选人来源耗尽或平台限制可能无法达目标 |
| 登录 | 微信/App切换、反馈、慢网络图片、监督交接 | 扫码及安全验证由本人完成 |
| 联系 | 独立 greet/message、批量预览、自动招呼、岗位暂停、回执 | uncertain 需人工核验，不自动重发 |
| 实时沟通 | 原生会话、消息、简历、附件及原生申请 | 共用浏览器，需与筛选协调 |
| 招聘跟进 | 档案、面试、Offer审批、入职清单 | 无电子签章、候选人自助签署或材料托管 |
| AI / 语义 | 同义词、旧规则 shadow、招聘 AI 辅助分析 | 需要岗位效果评估，模型建议不等于录用决定 |
| 部署运维 | 持久化卷、预检、不可变镜像、备份和隔离测试 | 需继续完善恢复演练与可观察性 |

## 当前优先事项

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| 高 | 换账号后的配置迁移体验 | 展示旧/新岗位 ID及状态、逐项差异和明确确认；发布新规则及新任务，保留历史和幂等；不按名称自动错绑 |
| 高 | 任务等待原因更直观 | 分清岗位失效、同账号排队、沟通占用、简历重试、目标达成、日上限和来源耗尽 |
| 高 | 修复既有 Web lint 基线 | `immediate-start-dialog.tsx` effect问题修复并通过相关检查，不只是压制警告 |
| 中 | 运行观察与交班 | 自动汇总各任务采集/精筛/成功招呼、等待时间及计划状态，数据来自相同口径 |
| 中 | 真实异常与恢复验证 | 在自然出现且获授权的场景验证简历不完整、来源失效、风险停止和不确定回执，不人为制造重复外部动作 |
| 中 | 持续文档对账 | 行为变化同步现行手册，发布快照带日期，新增历史报告纳入索引 |
