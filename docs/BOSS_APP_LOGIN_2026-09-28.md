# 微信与 BOSS App 扫码切换（2026-09-28）

## 现场原因

线上 `7fe8132` 的 BOSS 登录页出现官方提示：“为更好保障您的招聘安全，请使用BOSS直聘APP扫码登录”。微信扫码没有完成网页登录。旧 relay 只检查 URL 是否离开登录页，控制台也只在首次进入或手动刷新时加载图片，所以一直显示原微信二维码和等待扫码状态。

## 修改

- 登录页增加「微信扫码 / BOSS App 扫码」按钮。使用 BOSS 原生切换入口，二维码、使用说明和选中状态同步变化。
- API 验证可选的 `loginMethod`，沿用管理员权限和原子领取的刷新请求。后台在处理请求前保存选择，普通刷新和故障重启保留该方式；没有保存选择时仍默认微信。
- 仅在明确识别上述官方 App 提示、且已选择 App 方式时点击原生「去扫码」。其他安全验证仍停止，不代替人扫码或确认登录。
- 每次状态观察同步弹窗、过期、扫码确认和二维码变化；只在画面内容变化时更新截图。前端根据图片版本加载新图，切换期间隐藏旧图，过期的图片请求不会覆盖新状态。
- 尚未完成认证时，页面明确显示自动操作暂停，不再把服务版本一致误写成已经登录。

不改数据库、不更改业务队列或联系开关，不清空或替换浏览器登录卷。

## 验证

- TypeScript 检查通过，变更的登录页面 lint 通过。
- Linux amd64、断网容器：152 个测试文件、1080 项测试通过。
- Chromium 隔离 fixture：微信原有 9 种流程、新增 App 双向切换和实际 relay 14 种检查通过，包括明确 App 提示、二维码变更、重启保留方式，以及安全验证状态不响应刷新。
- 控制台隔离浏览器：两种方式的请求、自动更新图片、风控禁用按钮、桌面和 390px 手机布局通过；无页面异常或横向溢出。
- 全量 Web lint 存在本次之前的 `immediate-start-dialog.tsx:39` 同步 effect setState 错误；本次未改该组件。Mac 上 boss-cli help 子进程超时，Linux 同项已通过。

真实账号最终登录仍由管理员在手机上扫码并确认，以控制台的认证状态和后台心跳为准。
