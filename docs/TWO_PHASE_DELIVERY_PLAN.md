# Boss-Forge 两阶段交付计划

## 1. 交付策略

可以优先完成两个业务阶段，但必须先让第一阶段形成可验证的人工闭环，再开放第二阶段的自动联系开关。两阶段共用同一套候选人、规则、任务、联系和审计数据，不另造一套自动化系统。

## 3. 开发顺序

### M1：立即筛选与待审核列表

1. 建立岗位、规则版本、任务、候选人、岗位候选关系和证据模型。
2. Dashboard 保存岗位与筛选条件，点击“立即执行”后创建任务。
3. Worker 调用 `boss-cli` 获取候选人，进行标准化、去重和版本化规则评估。
4. 符合、有歧义和信息不足的候选人进入审核台，并显示原文证据。

### M2：定时执行与人工打招呼

1. 支持一次性、按日/工作日和按周执行，同一 BOSS 账号严格串行。
2. HR 可逐个通过或拒绝候选人，并记录备注与规则纠错。
3. 审核通过后，先预览消息，再由 HR 明确点击确认。
4. 联系意图使用 Outbox 和幂等键；结果不确定时停止重试并转人工复核。

### M3：第一阶段试运行

1. 连续试运行 2～4 周，统计规则准确率、召回率、有歧义率和重复联系率。
2. HR 纠错经管理员审核后进入新词典版本，历史结果保持可追溯。
3. 业务负责人确认指标达标后，才能进入自动联系上线审批。

### M4：受控自动打招呼

1. 只有高置信度、无冲突且通过全部硬性条件的候选人可进入自动联系。
2. 全局、岗位和任务三级开关必须同时开启，任一关闭都立即停止新联系。
3. 每次执行前重新检查时段、限额、冷却期、幂等和熔断状态，异常时安全停止。
4. 所有开关变更和联系结果写入审计日志。

## 4. 安全边界

- 在第一阶段正式验收之前，不会开启真实自动打招呼。
- 任何真实 `greet` 验收都需要单独授权，默认测试只到预览和策略判定。
- Dashboard 不直接操作浏览器，只通过服务端适配层调用锁定版本的 `boss-cli`。
- 自动联系不对“有歧义”和“信息不足”候选人开放。
