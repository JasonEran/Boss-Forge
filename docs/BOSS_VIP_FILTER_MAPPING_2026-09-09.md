## 使用方式

岗位规则第一步改为「BOSS VIP 筛选」，统一使用「一键获取 BOSS VIP 筛选」。从绑定岗位获取 VIP 和普通筛选的字段、名称、真实选项、单多选方式、年龄范围和可用状态，专业同时读取完整目录。移除原来写死的学历、经验、院校、活跃度和近期未看过选项。

获取保留平台已有选择，不导入或覆盖为 BOSS 当前选中条件。保存规则时一并保存选项快照，重新打开同一绑定岗位时直接复用，不必再单独获取专业和关键词；需要最新选项时点击同一个按钮刷新。新获取的选项缺失、权益不可用、选择超限、年龄超范围或存在明确互斥时提示调整，保留旧选择供移除。

## 字段覆盖

| 官方字段 | 平台控件 |
| --- | --- |
| age / 年龄 | 最低、最高年龄与不限，按原生范围生成 |
| activation / 活跃度 | 官方单选 |
| gender / 性别 | 官方单选，不自动推导 |
| keyword1 / 牛人关键词 | 岗位专属选项 |
| recentNotView / 近期未看过 | 官方单选 |
| exchangeResumeWithColleague / 是否与同事交换简历 | 官方单选 |

| firstDegree / 第一学历 | 读取院校附加配置；仅在官方提供时展示 |
| major / 专业 | 完整目录、搜索、分类、新旧名称映射，最多 5 个 |
| switchJobFrequency / 跳槽频率 | 官方单选 |
| experience / 经验 | 包含官方当前提供的毕业届别和经验区间 |

| degree / 学历 | 使用官方选择方式 |

最终字段顺序、名称、单多选和 VIP/普通分组来源由账号及岗位的原生定义决定。当前实现覆盖 14 个字段，遇到未知字段会报错，不静默忽略。旧版 auto/off 和仅专业/关键词快照仍兼容。

## 获取与执行

- 通过现有 position API 和账号 IPC 请求获取整套快照；核对平台岗位 ID、IPC 返回岗位 ID 和原生 Filter 组件的 jobId。
- BOSS 组件来源核对：[官方 v6429 app.js](https://static.zhipin.com/zhipin-boss/recommend/v6429/static/js/app.js)。读取 vipFilter$/normalFilter$、firstDegreeOption 和已确认状态；不猜测选项代码。
- 按官方 Filters、CheckBox 和 FirstDegree 的交互应用选项。年龄通过 VueSlider 原生 change 事件触发联动。其他选项点击原生控件，并使用 CheckItem.optionItem.name 核对完整名称，避免截断文案造成丢项。
- 执行前检查其他字段，再更新必要的专业预设；清除上次条件后应用完整计划。原生单多选、第一学历和年龄均参与应用前后读回。已生效的相同计划不重复刷新推荐列表。
- 静态同类互斥和隐藏第一学历的条件回传给表单；跨字段启用/禁用的时序由 BOSS 原生处理，最终有冲突或未完整生效时停止采集。
- 原有 fields 存储扩展覆盖全部字段。年龄使用两个字符串（如 `22`、`不限`），不保存 BOSS 的范围哨兵代码。optionsSnapshot 只用于编辑重开，不进入不可变任务筛选计划。候选来源验证对所有字段进行比较。
- 使用现有 JSON 配置字段，无数据库迁移。
