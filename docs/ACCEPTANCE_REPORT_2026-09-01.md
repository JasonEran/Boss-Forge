## 1. 验收结论

**自动化、服务级和完整浏览器 E2E 均已完成；本轮发现的筛选准确性、移动导航、表单可访问性和触控尺寸问题均已整改，当前 R1–R6 Fake-only 验收结论为通过。**

本轮真实浏览器验收首先发现 Base UI Button 在 `<form>` 内默认为 `type="button"`，导致登录按钮及 23 个业务提交按钮无法提交。现已为 24 个按钮显式补齐 `type="submit"`，并增加回归测试防止再次遗漏。

随后修复 TEM8 “今年三月考”等计划考试语境，词典升级为 `2026.09.1`；迁移 016、017 将存量误判改为 `ambiguous`、取消可能存在的待执行联系并清理派生英语等级。张童童的存量结果已从“符合 95% / TEM-8”纠正为“有歧义 60% / TEM-4、CET-4”。

移动端导航现统一覆盖 13 个路由，业务表单均有可见标签或明确的 ARIA 名称，移动端可操作控件达到 44px，候选人表格的审核操作在 320px 首屏保持可见。管理员登录、核心 Dialog、分页、消息预览、规则树、表单校验、自动联系就绪检查和退出登录均已在浏览器中实际操作。用户 E2E 与浏览器安全提示均确认 `realGreetingExecuted: false`，本次没有调用真实打招呼。

本轮还补齐了岗位基本信息编辑和按岗位维护联系消息模板。消息模板使用受控变量并保留不可变版本。岗位信息、当前生效规则、待发布版本和规则编辑现已统一到岗位设置页；智能同义词采用大语言模型生成、预览、应用/取消流程，高级参数默认折叠。旧筛选规则和识别治理页面改为岗位页兼容跳转。

功能冲突整改将 13 个平铺入口收敛为 7 个角色化一级模块，保留原 URL 作为模块子页；已有岗位规则统一在 `/positions` 编辑，自动联系状态统一在 `/automation` 配置，运营告警只在 `/operations` 处理。岗位选择的语义模式和目录版本现已进入 Worker，试运行/关闭结果不会参与通过或淘汰；人工审核会同步招聘阶段，待审核候选人不能绕过审核推进。

## 6. 范围边界与上线建议

- 首次试用前修改默认管理员密码并创建实际 HR 成员账号。
- 语义模型保持 `off` 或 `shadow`，直到真实岗位金标集达到准入指标。
- 真实联系 Worker 仍不部署；如未来开放，必须另行进行账号、额度、时间窗和紧急停止专项验收。
- 权威 BOSS 账号健康/回复同步 Worker、真实模型岗位效果和二进制附件上传仍属于后续上线工作，不影响当前 R1–R6 Fake-only 通过结论。
