## 用户可见行为

- 会话来源改为 BOSS 原生沟通栏，包括此前直接在 BOSS 沟通过、没有通过本平台发送打招呼的人。导入会话不会创建新的筛选候选人或筛选任务。
- 列表显示最近 7 × 24 小时有消息的会话，按最新消息排序。旧记录保留在数据库；旧会话收到新回复后会重新进入列表。
- 进入实时沟通、完成与筛选的交接后，自动读取会话列表及当前打开的聊天。每轮完成后约 5 秒开始下一轮，因此实际更新间隔还包含 BOSS 加载耗时。无需逐个打开会话才能发现未读回复。
- 页面显示同步时间（精确到秒）、未读会话数、刷新失败及读取不完整提示。一次列表刷新失败不会阻止当前聊天刷新；请求串行执行，避免重叠。
- 切回其他页面或页面不可见后暂停沟通同步，沿用原有浏览器使用权交接机制。发送操作等待当前读取结束，再执行；草稿按用户和会话保留。
- “常用语”仅保存在本平台，按用户独立管理，支持新增、编辑、删除，最多 50 条，每条最多 500 字。点击后追加到草稿，不会自动发送；超过消息字数上限时保留原草稿并提示。
- “交换微信”映射到 BOSS 原生“换微信”按钮和原生确认弹层。平台确认框固定展示申请对象；BOSS 按钮不可用时同步禁用。已申请、已交换、结果待确认分别显示，结果不确定时禁止重复申请。

## 实现与数据兼容

主要入口：

| 层 | 文件 |
| --- | --- |
| 页面与刷新 | `apps/web/app/communication/communication-client.tsx`、`refresh-loop.ts`、`quick-replies-dialog.tsx` |
| API 与并发合并 | `apps/control-api/src/communication-routes.ts`、`communication-sync.ts` |
| BOSS 原生读取与操作 | `apps/boss-worker/src/boss-communication.ts`、`boss-wechat.ts`、`session-supervisor.ts` |
| 账号绑定的 IPC | `packages/boss-cli-adapter/src/browser-control-ipc.ts` |
| 数据与协议 | `packages/data/src/communication-repository.ts`、`packages/contracts/src/communication.ts` |
| 数据库升级 | `packages/data/migrations/038_boss_communication_inbox.sql` |

原生列表读取使用 BOSS 虚拟列表的 `dataSources`、加密候选人编号、岗位编号、最后消息时间及未读数。翻页读取到一周边界；置顶旧会话不会提前终止扫描。最多返回 2,000 个会话，达到上限、日期不可信或加载范围不确定时提示读取不完整。前端分批显示，每批 100 个。

038 将会话与筛选候选人解耦。旧会话继续使用原候选人 UUID，保留已有地址、消息编号、BOSS 回执及已读标记；新原生会话可以没有筛选候选人。该迁移须与新版 API、worker 一起上线，不支持仅回退旧应用而保留新表结构。未来发布前应按既有流程备份数据库。

岗位和部门权限继续生效；普通招聘人员仅可访问分配岗位的会话。账号下尚未导入岗位的原生会话仅对有该账号岗位权限的管理员开放；已属于其他部门岗位的会话不会被视作“未绑定岗位”。发送与微信交换保留原有联系开关、紧急停止、禁止联系、账号健康验证及浏览器使用权检查。

微信交换使用持久化请求编号及状态，不以“按钮点击成功”作为发送成功。只有新的原生请求提示、原生待确认状态或已确认的微信互动卡片，才记录请求已发出；请求已发出不等于对方已同意交换。失败或超时不会自动重发。
