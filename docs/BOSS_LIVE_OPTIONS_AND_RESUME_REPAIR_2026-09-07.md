## 本次需求与实现

- 岗位规则的官方筛选增加“获取最新选项”：通过已登录的 BOSS 浏览器，按当前绑定的岗位 ID 获取专业与牛人关键词；使用真实选项按钮选择。刷新保留现有选择，已失效项可移除，保存时拒绝仍失效的选择。反馈包含加载中、失败重试、更新时间；取消不保存规则。
- “非工作时间段暂停”按用户要求暂时关闭：生产 `workdayStartHour=0`、`workdayEndHour=24`。原 9–18 配置已备份；其他查看额度与联系控制保持原配置。
- 完整简历中没有识别到明确的岗位资格证据，按用户要求判为未通过。规则明确否定或证据不足均有可读理由；已经完整读取才进入此判断，读取失败先恢复/重试。旧流程保持兼容；官方筛选来源未能验证属于技术问题，不能据此判定候选人不符合。

## 简历读取修复

实际失败日志为 `resume sections are still collapsed` 和 `resume segment 3 has not painted`。

1. BOSS WASM 简历采用专用读取路径，保留原页面尺寸和原滚动布局。通过外层滚动获取实际画布分段像素，检查像素稳定、内容高度、分段连续性和最后一段覆盖。改变视口尺寸会重建 WASM 状态，导致刚展开的内容再次折叠；专用路径避免了这个根因，并将透明画布合成到白底，保证预览与 OCR 清晰。
2. 展开按钮优先使用 OCR 字符坐标；使用临时定位点让原有父容器滚动，保持 c-resume 内层窗口滚动为 0，避免 WASM 点击坐标偏移。只展开简历内容，排除“查看全部 8 项分析”等 VIP 分析入口。
3. 其他 DOM/SVG/静态画布简历保留通用截图路径。均衡分段避免最后一段只剩空白页尾；纯画布回退按实际画布覆盖范围截取。仍拒绝真正未绘制、缺段或不稳定的截图。
4. 继续查找推荐列表改为滚动实际 document.scrollingElement；生产 BODY 设置 scrollTop 不移动，原先会反复读取首屏。每次滚动到当前列表底部以加载下一批，仍限制读取批数并核对身份。
5. 后台等待账号锁的计时器保持进程存活。原代码在数据库连接闲置后可提前退出 0，留下 processing 状态。独立 Node 子进程测试在修复前稳定失败，修复后通过。
