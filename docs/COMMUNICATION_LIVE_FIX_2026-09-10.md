# 实时沟通线上同步修复

2026-09-10，登录恢复后的真实账号验收发现并修复以下问题：

- BOSS 使用 `boss-virtual-list`，`.user-list` 为 `overflow:hidden`，仅渲染 40 行。较早的联系人已在原生 `dataSources` 中但没有 DOM 行，原来的普通滚动定位会漏掉。现使用原生列表数据按稳定候选人 ID 查找、`scrollToIndex` 定位后点击，并再次核对打开的会话 ID；需要下一页时使用 `scrollToBottom` 触发原生加载。不按姓名匹配。
- BOSS 重新读取历史消息后，服务端编号位于 `mid`，`received:true` 表明消息由服务端返回；状态 1 为送达、2 为已读。原实现只读取发出消息的 `serverMid`，造成已有发出消息缺失。现兼容这两种已确认状态，仍排除未确认的本地气泡。
- 已缓存消息会遮盖较新的列表预览。新增 `036_communication_preview_time.sql` 保存 BOSS 最新消息时间，让较新的预览和排序先更新，无需先打开对应会话。
- BOSS 在线标识与数据库内发送所需的权威健康记录不同，过期记录会误阻止回复。聊天读取成功后由 supervisor 再次通过 CDP 检查登录并更新权威健康记录；发送接口先校验确切会话再检查全部联系规则，随后才允许排队。没有跳过禁止联系、权限、风控或联系开关。
- BOSS 的 `messageType:4` 服务推广会借用当前候选人的来源 ID。现将其归为系统消息，不增加候选人未读数，也不抢占最后一条聊天预览；重新同步时修正已经缓存的消息分类。
- `bizType:21050004` 的「沟通职位」背景卡片同样归为系统消息，避免旧职位卡被当作候选人新回复。
- 手机尺寸或横竖屏变化时，正在看最新消息的会话继续保持在底部；主动翻看历史时保留阅读位置。
- 底层 `assertCurrentConversationMatches` 仍要求旧 DOM 中存在候选人 ID，导致当前 BOSS 页面发送前报 `BOSS_SEND_TARGET_MISMATCH`。改为核对唯一可见原生会话的稳定 ID，同时拒绝可见列表与会话 ID 冲突、缺失、多会话或多个不同 ID。保留正文及服务端回执核验，不改为姓名发送。

测试包含未渲染的第 71 个联系人定位、冲突标识拒绝、送达／已读历史读取、本地气泡排除，以及真实 PostgreSQL 的新预览时间、未读与排序验证。线上读取测试不会向真实候选人发送测试消息。
