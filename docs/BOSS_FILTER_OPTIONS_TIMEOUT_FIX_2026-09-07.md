# 专业与牛人关键词获取超时修复

日期：2026-09-07；生产 release：`boss-options-fix-20260907-2250cst`。

## 原因和修改

线上日志出现 `BOSS browser read failed: Timed out after waiting 10000ms`，当时 BOSS 登录与 Worker 均正常、候选人和任务为 0。选项读取复用了岗位切换流程，输入岗位搜索词后等待整个页面 network idle；BOSS 后台聊天、状态及统计请求持续运行时，岗位下拉已就绪仍可能超时。

- 岗位搜索改为等待输入词和过滤后的岗位选项实际渲染，继续按绑定 ID 精确选择，同名岗位不回退猜测。
- 仅读专业和关键词时，等待目标岗位切换结果及筛选面板，不等待候选人网络活动结束。候选人采集路径仍保留列表刷新等待，避免误读上个岗位的候选人。
- 首次进入推荐页也纳入推荐 iframe 重建重试。显式刷新仍从当前 BOSS 获取定义，不使用旧缓存冒充实时选项。

## 验证

- 本地浏览器夹具持续保持三个聊天 / 状态 / 统计请求未完成，确认 network idle 会超时；新选项路径成功处理延迟搜索结果、同名岗位的不同 ID，不重复切换当前岗位，缺失 ID 明确拒绝。没有读取候选人。
- 服务器现有 5 个 BOSS 岗位均读取成功，每个返回 5 个专业、9 个关键词，约 3.5–4.6 秒；不同岗位返回不同专业 / 关键词，绑定 ID 一致。
