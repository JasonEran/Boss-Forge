# 招聘使用手册

> 面向 HR、招聘负责人和管理员；按 2026-09-29 应用代码整理。

## 1. 找到正确入口

| 页面 | 用途 |
| --- | --- |
| 工作台 `/` | 查看概览、最近任务和待处理事项 |
| 岗位设置 `/positions` | 同步 BOSS 岗位、分配负责人、编辑和发布规则 |
| 任务与计划 `/tasks` | 立即开始、未来计划、任务进度、取消和重试 |
| 候选人 `/candidates` | 核对筛选结论、简历、证据及人工审核 |
| 联系 `/contacts` | 招呼/消息预览、批量操作、模板、岗位联系执行开关 |
| 实时沟通 `/communication` | BOSS 会话、回复、在线/附件简历和原生申请 |
| 招聘流程 `/pipeline` | 招聘档案、面试、Offer、入职及跟进 |
| 招聘运营 `/operations`、`/analytics` | 运营事项与分析 |
| 系统设置 `/team` | 团队权限；Tab 包含 BOSS 登录、联系安全、审计 |

导航随角色变化。面试官只访问其有权查看的候选人/面试信息；页面隐藏不替代服务端权限校验。旧 `/rules`、`/semantic` 会跳回岗位设置。

## 2. 登录 BOSS

先用控制台账号登录，再由管理员或招聘负责人进入 **系统设置 → BOSS 扫码登录**。

1. 选择“微信扫码”或“BOSS App 扫码”，使用对应手机应用扫码并确认。
2. 如 BOSS 明确要求 App 验证，切换到 BOSS App；等待新二维码显示后再扫。
3. 手机确认后，等待控制台显示认证成功和 Worker 就绪。手机显示成功并不保证后台交接已完成。
4. 过期时手动刷新；连接故障时使用“重新连接扫码服务”，会保留已选扫码方式。不要连续点击。
5. 出现验证码或安全验证，由本人在 BOSS 官方页面处理；不要反复重启或清空登录资料。

控制台会观察状态并加载更新后的二维码画面，不会通过不断自动刷新来替人过验证。换扫码方式只是换登录入口，不会自动迁移另一个账号的岗位、规则和任务。

## 3. 同步岗位与发布规则

1. 确认当前登录的是要使用的 BOSS 账号。
2. 到岗位设置同步岗位，选择当前账号的**开放岗位**，核对状态和同步时间。
3. 核对负责人、可访问成员和当前生效规则。新导入岗位可能没有规则；“岗位已同步”不等于“可以开始任务”。
4. 编辑规则，读取该岗位的官方筛选选项，配置与岗位能力相关的条件、简历证据要求和缺失处理。
5. 保存新版本并由有权角色发布。草稿不会生效，已排队任务使用自己的规则快照。

同名不代表同一个岗位。旧岗位显示“本次同步未找到”时，应按[账号切换手册](BOSS_ACCOUNT_SWITCH.md)恢复，不能直接重试旧任务或仅修改名称。

## 4. 立即开始与计划

选择岗位后打开“立即开始”，核对来源、目标人数和“自动打招呼”开关。

| 设置 | 人数目标的实际含义 |
| --- | --- |
| 自动打招呼开启 | 本任务成功打招呼人数；只有 `greet + sent` 计入 |
| 自动打招呼关闭 | 完成简历精筛且规则通过的人数 |

“已采集”“已查看”“筛通过”“发送成功”是不同计数。未匹配、简历失败和发送失败不会充抵目标。默认目标 20，可配置范围 1–100000；这不改变账号每日招呼限制。系统每波处理最多 20 人，再按进度继续。

计划支持单次、每天、工作日、每周，按上海时间执行。立即任务与计划各自保存自动打招呼设置；修改其中一个不会同步改另一个。停用计划阻止后续生成任务，不等于取消已经生成的任务。

### 今天要跑两个岗位

为两个岗位分别建立任务，分别检查规则、人数和自动打招呼开关。一个 BOSS 会话串行执行，另一个显示排队可以是正常状态；不要为“同时运行”再开一个 Worker。两个岗位各 100 是两个目标，账号默认日上限 200 是共享上限，并不保证一定有足够合格候选人。

## 5. 看懂进度与等待

| 界面 / 原因 | 含义与处理 |
| --- | --- |
| 排队 | 等待同账号前面的工作或当前浏览器操作结束 |
| 筛选中 | 正在采集或处理简历；结合最后进度时间判断 |
| 等待简历重试 | 查看预计重试时间；此前完成结果保留，不要重复创建任务 |
| 已达到目标 | 筛通过人数或成功招呼人数达标，停止下一波 |
| 推荐池无新增 | 本次来源已经耗尽，可能未达到目标 |
| 每日招呼上限 / 已停用 | 系统按账号日上限停止任务及相关计划；不要清零计数强行继续 |
| 找不到绑定岗位 | 先查账号与岗位 ID，再查开放状态；按账号切换流程处理 |
| 待人工核验 | 联系结果不明，先在 BOSS 核实，不能直接重发 |

更详细的状态码和只读检查见[运维手册](OPERATIONS_RUNBOOK.md)。看到 Worker 空闲，也要确认是否已经没有可领取任务。

## 6. 审核与联系

在候选人详情核对卡片、简历图片、规则版本和逐项证据。“未识别”表示证据不足，不应写成已满足条件。人工改判填写依据，系统保留原机器结论。

- 手工招呼和正文消息是独立动作；核对候选人、岗位、账号和预览正文后再确认。
- 批量联系先看预览及不可执行原因，只提交符合当前条件的对象。
- 自动招呼由明确开启该功能的任务触发，仍受岗位、账号、队列、回执及日上限检查。
- “本岗位联系执行”暂停只阻止下一次领取，已开始的一次动作可能仍会完成；排队数据会保留。
- 结果待核验时先核对 BOSS 实际会话。只有确认已发送或确认未发送后，才使用相应核验操作。

## 7. 实时沟通与招聘跟进

进入实时沟通后，系统协调同一浏览器的使用；正在进行的操作收尾后再切换，离开页面后恢复后台任务。不要把聊天占用浏览器误认成 Worker 卡死。

在线简历先返回图片，后台识别/分析继续更新。附件简历的接收、求简历、换微信和消息发送均有独立动作及对象确认；查看附件不等于发出请求。

从会话建立招聘档案后，可跟进面试、Offer 和入职。邀请预览只准备聊天草稿，点击发送才产生外部消息。候选人的接受/拒绝与实际入职由 HR 根据事实登记；系统不替候选人作决定。

## 8. 需要运维时提供什么

提供岗位名称、任务 ID、发生时间、控制台状态和错误原文即可。无需发送服务器密码、Cookie、手机二维码或完整候选人简历。运维应先核对状态与日志，保留已完成结果后再处理。
