## 使用流程

1. 管理员在“设置 → BOSS 登录”登录同一个 BOSS 账号。
2. 在“岗位设置”点击“同步 BOSS 岗位”。读取 BOSS 职位管理列表及分页，显示招聘状态和同步时间，不再手动创建内部岗位或填写匹配关键词。
3. 为每个岗位添加独立规则。管理员/招聘负责人可发布；HR 保留提交负责人发布的原流程。
4. 管理员在“团队与权限”创建平台账号、分配岗位。HR 登录后可以在自己的岗位间切换，规则、任务和候选人视图随岗位变化。
5. 点击“开始筛选”或定时任务到期后，后台持有同一账号锁，在 BOSS 推荐牛人右上角切换绑定岗位，等待列表更新后读取候选人；精筛也恢复这个任务的岗位。同一 BOSS 账号依次执行任务。

页面选择岗位只改变工作台视图；真正的 BOSS 下拉切换发生在后台执行任务时。

## 实现与历史数据

- migration 028 增加 BOSS 岗位 ID、原始状态、同步时间和名称唯一性；任务插入时记录岗位 ID/名称快照，同时覆盖即时与定时任务。
- 岗位以“BOSS 账号 + BOSS 岗位 ID”唯一识别。相同名称、不同 ID 的岗位可并存。旧岗位名唯一约束改为仅适用未绑定岗位的部分索引。
- 唯一同名的旧岗位自动关联并保留内部 ID、规则、成员、候选人和任务。名称不能明确对应时保留为“待关联”，管理员可把尚无规则、任务或其他配置的新同步岗位关联到旧岗位。
- 同步不覆盖任何规则。完整列表中没有再出现的已绑定岗位暂停新筛选，历史数据保留；列表不完整或读取失败时不写入同步结果。
- 推荐下拉优先使用 BOSS 岗位 ID；旧版下拉不暴露 ID 时，仅允许整个同步目录中名称唯一的岗位按完整名称匹配。名称包含匹配已从已绑定岗位的筛选路径移除；不唯一、不可用或无法确认时返回明确错误。
- 任务身份按保存的 ID 恢复。若同一 BOSS ID 后续改名，以最新同步名称查找，保留任务原始名称快照。精筛仍保留 migration 027 的实际采集岗位回退。
- UI 删除手工新建岗位路径，规则表单全部条件保留；补充同步进度、未登录/忙碌/不完整读取提示、旧岗位关联和 HR 分配说明；Spotlight 与完整导览同步更新。
- 历史内部 API/集成的手工岗位入口保留兼容；已同步 BOSS 的账号未绑定岗位不能再创建推荐任务或定时筛选。旧任务恢复兼容路径仍保留。
