# Boss-Forge 产品需求

> 产品形态：内网 HR 招聘控制面
>
> 当前阶段：release `audit-events-20260904-1614cst` 已生产部署，独立真实 greet/message 与逐候选人签名许可已上线；runtime real、全局/部门控制 safe-off，首次真实写入尚未验收；语义仅 off/shadow

## 1. 产品目标

不同 HR 可以按岗位配置不同筛选条件，系统从 BOSS 推荐或搜索结果获取候选人，必要时预览完整简历并 OCR，给出可追溯的规则结论，最后由 HR 审核。

目标流程分两阶段：

1. 人工阶段：系统列出符合、歧义和信息不足的候选人，HR 核对证据后决定是否联系。
2. 联系阶段：系统分别生成岗位招呼语或联系正文的精确预览，由 HR 核对候选人、BOSS 发件账号和完整正文。每个动作必须取得独立短效签名许可，并受全局熔断、限额、时段、冷却、幂等和发送前重验约束。

筛选闭环和三简历生产验收已完成；历史证据见状态文档。当前代码已通过 523 项单元测试、migration 001–026、隔离数据集成和隔离用户/联系 E2E，隔离 E2E 明确不执行真实 BOSS 写入。双动作真实传输已部署，但全局/部门控制 safe-off；当前没有符合条件且已审核通过的候选人，首次真实 canary 尚未验收。生产语义连接保持 off，恢复 shadow 前必须先轮换提供方凭据。

## 2. 用户与权限

系统包含 HR、招聘负责人、面试官和管理员四类角色。HR 与面试官只查看被分配岗位；招聘负责人和管理员可管理本部门岗位。会话身份由服务端解析，前端传入的 `createdBy`、`reviewerId` 和 `actorId` 不作为授权或审计身份。

## 3. 岗位与规则

每个岗位至少包含：

- 岗位名称、BOSS 账号逻辑 ID、BOSS 岗位关键词和负责人名称。
- 一个当前生效规则版本；保存编辑会创建新版本，不覆盖旧版本。
- 推荐牛人或普通搜索两种筛选来源。

管理员和招聘负责人可以编辑岗位名称、BOSS 岗位关键词和负责人名称。编辑保留岗位 ID，并增加岗位版本号和审计记录，避免破坏候选人、规则和任务的已有引用。

当前结构化规则表单支持：

- 根节点 AND 或 OR。
- CET-6 或 TEM-8 满足任一、语言证据与最低置信度。
- BOSS 平台 `985`、`211`、`双一流`标签，支持任一或全部。
- 年龄范围、最晚毕业年份、应届/往届/不限和性别（缺失时不猜测）。
- 工作年限最小值/最大值。
- 最低学历。
- 技能关键词、地点和简历全文关键词，支持任一或全部。
- 缺失信息策略：人工复核、失败或忽略。

岗位设置页提供规则编辑、版本创建和负责人发布；已发布配置不可原地修改。旧 `/rules` 仅保留兼容跳转，复杂模板、历史回放和回滚能力继续由后端接口保留，不再作为普通 HR 的独立页面。

## 4. 通用语义筛选

语义归一化是所有岗位的通用能力，不是 TEM8 专项功能。不同简历可能用缩写、别名、行业术语、非标准写法或项目描述表达同一事实；岗位也可能要求证书、技能、行业经历、管理经验、项目规模或业务结果等不同类型的条件。

系统在内部按条件类型选择执行方式，普通 HR 不直接选择技术模式：

| 模式 | 适用条件 | 主要执行者 |
|---|---|---|
| 平台标签 | BOSS 明确提供的 985/211/双一流等标签 | 适配器 + 规则引擎 |
| 确定性规则 | 学历、地点、工作年限、分数、明确证书 | 解析器 + 规则引擎 |
| 归一化实体 | 技能、证书、职能和行业的缩写、别名及变体 | 同义词库；无法确定时由大模型提取 |
| 语义评分标准 | 项目主导、管理经验、行业深度、从 0 到 1 等上下文条件 | 大模型按版本化评分标准评估 |

目标处理链路为：

```text
BOSS 卡片/简历/OCR
  -> 确定性解析与同义词归一
  -> 未识别或存在歧义时调用大模型
  -> 严格 JSON Schema 校验
  -> 生成统一候选人事实
  -> 规则引擎按岗位条件判断
  -> 低置信度、证据冲突或信息缺失进入人工审核
```

大模型负责事实提取和受控的语义评估，不得直接生成不可解释的最终录用结论。每条模型结果至少保存：

- 条件 ID、规范化事实和值域限定词，例如“已通过”“备考中”“参与”“主导”。
- 一段或多段简历原文证据及来源快照。
- 置信度、提取器类型、模型版本、提示词版本和语义目录版本。
- `matched`、`not_matched` 或 `unknown` 的评估结果与原因码。

没有原文证据、输出不符合 Schema、不同证据互相矛盾或置信度低于岗位阈值时，结果必须为 `unknown` 并进入人工复核。HR 的纠正用于形成评估样本、补充同义词库或发布新规则版本，不得在没有审批和版本记录的情况下自动修改生产规则。

英语证书确定性归一支持 CET-6/TEM-8 及其常见写法。TEM-8 需要兼容 `TEM8`、`TEM-8`、`TEM 8`、`英语专业八级`、`专业英语八级`、`英语8级` 等表达，并区分已通过、未通过、备考/目标/要求以及其他英语等级；规则可明确表达“CET-6 或 TEM-8 任一满足”。未达到目标时，页面应展示识别到的当前英语级别。

985/211/双一流仍只使用 BOSS 候选人卡片的显式平台标签，不从学校名称、简历自述或大模型推断，也不需要导入学校名单。

当前代码已实现 schema 1.1、同义词优先匹配、OpenAI 兼容连接器、严格证据校验、部门语义目录、审批版本、固定评估集和指标。模型默认关闭，岗位只允许 off/shadow；旧的 alias substring 评估不能代表真实 criterion/rubric，`SEMANTIC_ACTIVE_DECISIONS_AVAILABLE=false`，migration 024 也把存量 active 降为 shadow。仓库不包含真实模型配置，影子结果不得改变招聘结论。

HR 在岗位规则中添加“智能同义词”条件时，只填写一个要识别的内容；点击按钮后由已配置的大语言模型生成候选同义词，必须经过预览并由用户选择应用或取消。高级置信度和手工映射默认折叠。旧“识别治理”页面不再显示；共享目录与固定验证继续由后端保留，但在完成代表性、逐准则的真实模型验收前不提供正式启用入口。

## 5. 执行方式

系统支持：

- 立即执行。
- 指定未来时间执行一次。
- 每天、工作日或每周周期执行。

定时计划到期后生成与立即执行相同的任务快照。搜索来源必须提供关键词。任务和计划创建请求必须携带幂等键。

## 6. 候选人与审核

系统优先用稳定 BOSS locator 去重自然人，并按“任务—候选人”保存独立筛选/审核状态；同一岗位的当前任务视图另有受约束的当前指针。重复候选人在新任务出现时不会迁走或覆盖旧任务的规则版本、证据和审核结果。候选人详情应包含：

- BOSS 卡片原始字段和采集证据。
- 当前规则版本和规则结论。
- 简历预览/OCR 状态。
- TEM8 或当前英语级别。
- 每个规则叶子的证据、置信度和原因码。
- 语义条件的规范化事实、证据、模型/提示词/语义目录/评分标准版本。
- 审核历史和联系状态。

HR 可以审核通过或拒绝，提交备注和纠错类型。审核采用预期版本号防止并发覆盖。

机器判定未通过或资料不足时，HR 可以有理由地人工覆盖；备注和纠错类型必填，机器原结论、原证据和版本保持不变并进入审计。

## 7. 联系

当前工作树的产品流程是：审核通过 → 选择“一键打招呼”或“发送消息” → 服务端生成该动作精确预览和短效签名许可 → HR 核对具体候选人、BOSS 发件账号和完整正文 → 只创建对应动作的一次意图。两个动作互不附带，许可不可互换。

历史 `acceptance2` Safari 验收时没有已批准候选人，因此联系页只展示示例模板，没有生成候选人级预览、没有请求一次性许可，也没有发送；当时页面如实显示真实联系编译关闭。当前 `contact-actions` release 已改为 runtime real、全局/部门控制 safe-off，联系队列、intent、attempt 和 authorization 仍均为 0。

模拟联系状态机仅用于显式隔离且允许 mock 联系 fixture 的测试；常规数据集成与用户 E2E 不创建真实联系记录。真实能力虽然已在工作树编译可用，默认部署仍为 disabled；real 模式、兼容总闸、部署签名密钥、supervisor 确认、四级开关和候选人级许可缺任一项都失败关闭。

管理员和招聘负责人可以在联系页按岗位编辑消息模板。模板支持 `candidate_name`、`position_name` 和 `hr_name` 三个受控变量；每次保存创建新版本，不覆盖历史版本。岗位模板优先于部门默认模板，未配置时自动继承默认模板。编辑或保存模板只改变后续预览内容，不会创建联系意图或发送消息。

联系安全控制面已保留：

- 全局、部门、岗位和任务开关、状态展示与审计；启用开关本身不会创建联系意图。
- 权限、DNC、紧急停止和每次候选人动作的签名预览确认。
- BOSS 账号健康、release、简历策略和 Worker 心跳的一致性检查。
- 回复同步、Do-Not-Contact 和账号健康数据结构/API。

生产已提供 Real Worker：通过 authenticated supervisor 的私有 IPC 复用现有浏览器，并在外部写前完成全局 fence 与最终重验；无法确认回执时进入 `uncertain` 且不自动重试。当前控制 safe-off 且联系数据为 0，尚未执行真实写入。首次 canary 必须先向用户展示唯一一个具体动作、候选人、BOSS 发件账号和完整正文，并取得对该组合与正文的精确许可。

## 8. 页面范围

主导航按角色呈现 7 个一级模块。14 个现有页面 URL 作为模块子页保留，避免破坏书签和深链接：

| 一级模块 | 子页与当前职责 |
|---|---|
| 工作台 | 候选人数、规则通过、待审核、联系数和最新任务 |
| 岗位设置 | 岗位信息；当前生效规则；待发布版本；唯一规则编辑入口；AI 同义词生成预览与应用 |
| 任务与计划 | 立即执行、创建计划、查看任务和停用计划 |
| 候选人 | 候选人审核；招聘流程、时间线、备注、待办、附件、面试和反馈 |
| 联系 | 按岗位编辑版本化消息模板；分别预览/确认“一键打招呼”和“发送消息”；联系安全设置保留四级开关、紧急停止和就绪状态 |
| 招聘运营 | BOSS 回复、人才库、账号健康、告警、导出和保留策略；漏斗、来源和审核分析 |
| 系统设置 | 成员、角色、岗位协作者和阶段配置；BOSS 扫码/会话状态；审计与安全边界 |

合理的低频功能继续保留在模块 Tab、角色可见范围或系统设置中；产品只合并同义、重复或失效入口，不以删除功能为目标。

## 9. 非功能要求

- 外部操作只能由 Worker 执行，浏览器不得直接调用 BOSS。
- 任务、审核、联系和计划必须幂等并保留审计。
- 候选人审核状态和招聘阶段必须一致：待审核不能进入后续阶段，通过和拒绝审核分别同步到“已通过”和“已淘汰”。
- 已发布规则版本不可原地修改。
- 简历预览开关与联系开关必须独立。
- 单个候选人失败不能丢失已完成结果。
- 大模型不可覆盖 BOSS 平台标签，不得在缺少原文证据时给出确定结论。
- 模型输出必须经过 Schema 校验；模型、提示词、评分标准和语义目录均需版本化并支持历史回放。
- 不从简历推断岗位无关的敏感个人属性；模型输入、输出和凭据不得离开批准的内网边界。
- 所有日期按 UTC 存储，计划业务时区当前固定为 `Asia/Shanghai`。
- 部署目标是受控内网；可选独立 TLS 网关用于跨公网访问，但不提供公网 SaaS、CDN、WAF、公共注册或公网数据库方案。

## 10. 当前验收口径

当前阶段通过标准：

- 岗位、规则、立即任务和定时计划可以通过 Dashboard 创建；岗位基本信息可以由管理角色编辑。
- 推荐/搜索结果可去重入库并进入简历精筛队列。
- 规则证据、TEM8 和当前英语级别可查看。
- HR 审核、岗位消息模板编辑、greet/message 精确预览和取消可重复执行；默认验收不创建真实联系数据。
- 自动化测试与隔离 E2E 明确断言没有真实打招呼或消息发送。

本地隔离的岗位—规则—任务—逐任务候选人—审核—双动作预览闭环，历史生产的 API/Web/HTTPS/Safari、登录保持与三简历验收，523 项单元测试和 migration 001–026 隔离集成/E2E，以及双动作生产部署属于已通过范围，产品结论为“基本够用”。首次真实 canary、真实内网模型效果和语义 active 不在通过范围。
