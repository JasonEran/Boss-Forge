# Boss-Forge 产品需求

> 产品形态：内网 HR 招聘控制面
>
> 当前阶段：筛选、人工审核与 Fake 联系闭环

## 1. 产品目标

不同 HR 可以按岗位配置不同筛选条件，系统从 BOSS 推荐或搜索结果获取候选人，必要时预览完整简历并 OCR，给出可追溯的规则结论，最后由 HR 审核。

目标流程分两阶段：

1. 人工阶段：系统列出符合、歧义和信息不足的候选人，HR 核对证据后决定是否联系。
2. 自动阶段：人工阶段准确率稳定后，按岗位显式开启自动联系，并继续受全局熔断、限额、时段、冷却和幂等约束。

当前代码只完成第一阶段的数据与 Fake 联系闭环；第二阶段尚未开放。

## 2. 用户与权限

目标角色包括 HR、招聘负责人、面试官和管理员。不同 HR 应只查看被分配岗位的数据。

当前版本没有登录、用户表、部门表或服务端数据权限。API 中的 `createdBy`、`reviewerId` 和 `actorId` 由前端传入，Dashboard 使用固定操作者标识。因此当前版本只适合受控内网单团队试用，不能作为多部门权限验收通过的依据。

## 3. 岗位与规则

每个岗位至少包含：

- 岗位名称、BOSS 账号逻辑 ID、BOSS 岗位关键词和负责人名称。
- 一个当前生效规则版本；保存编辑会创建新版本，不覆盖旧版本。
- 推荐牛人或普通搜索两种筛选来源。

当前结构化规则表单支持：

- 根节点 AND 或 OR。
- TEM8 与最低置信度。
- BOSS 平台 `985`、`211`、`双一流`标签，支持任一或全部。
- 工作年限最小值/最大值。
- 最低学历。
- 技能关键词、地点和简历全文关键词，支持任一或全部。
- 缺失信息策略：人工复核、失败或忽略。

规则引擎还支持嵌套 AND/OR/NOT、通用文本/枚举和自定义院校目录，但 Dashboard 暂无任意嵌套可视化编辑器。

## 4. 通用语义筛选

语义归一化是所有岗位的通用能力，不是 TEM8 专项功能。不同简历可能用缩写、别名、行业术语、非标准写法或项目描述表达同一事实；岗位也可能要求证书、技能、行业经历、管理经验、项目规模或业务结果等不同类型的条件。

每条岗位条件必须选择一种执行模式：

| 模式 | 适用条件 | 主要执行者 |
|---|---|---|
| 平台标签 | BOSS 明确提供的 985/211/双一流等标签 | 适配器 + 规则引擎 |
| 确定性规则 | 学历、地点、工作年限、分数、明确证书 | 解析器 + 规则引擎 |
| 归一化实体 | 技能、证书、职能和行业的缩写、别名及变体 | 同义词库；无法确定时由大模型提取 |
| 语义评分标准 | 项目主导、管理经验、行业深度、从 0 到 1 等上下文条件 | 大模型按版本化评分标准评估 |

目标处理链路为：

```text
BOSS 卡片/简历/OCR
  -> 确定性解析与同义词归一
  -> 未识别或存在歧义时调用大模型
  -> 严格 JSON Schema 校验
  -> 生成统一候选人事实
  -> 规则引擎按岗位条件判断
  -> 低置信度、证据冲突或信息缺失进入人工审核
```

大模型负责事实提取和受控的语义评估，不得直接生成不可解释的最终录用结论。每条模型结果至少保存：

- 条件 ID、规范化事实和值域限定词，例如“已通过”“备考中”“参与”“主导”。
- 一段或多段简历原文证据及来源快照。
- 置信度、提取器类型、模型版本、提示词版本和语义目录版本。
- `matched`、`not_matched` 或 `unknown` 的评估结果与原因码。

没有原文证据、输出不符合 Schema、不同证据互相矛盾或置信度低于岗位阈值时，结果必须为 `unknown` 并进入人工复核。HR 的纠正用于形成评估样本、补充同义词库或发布新规则版本，不得在没有审批和版本记录的情况下自动修改生产规则。

TEM8 是首个已实现的确定性归一化示例，需要兼容 `TEM8`、`TEM-8`、`TEM 8`、`英语专业八级`、`专业英语八级`、`英语8级` 等表达，并区分已通过、未通过、备考/目标/要求以及其他英语等级。未达到 TEM8 时，页面应展示识别到的当前英语级别。

985/211/双一流仍只使用 BOSS 候选人卡片的显式平台标签，不从学校名称、简历自述或大模型推断，也不需要导入学校名单。

当前代码已实现 schema 1.1 语义条件、岗位表单、同义词优先匹配、OpenAI 兼容模型连接器、严格输出/原文证据校验、影子/生效模式、失败关闭和结果持久化。模型默认关闭，仓库没有可用于效果验收的真实模型配置；部门级语义目录审批、批量回放和评估集仍是下一阶段目标。

## 5. 执行方式

系统支持：

- 立即执行。
- 指定未来时间执行一次。
- 每天、工作日或每周周期执行。

定时计划到期后生成与立即执行相同的任务快照。搜索来源必须提供关键词。任务和计划创建请求必须携带幂等键。

## 6. 候选人与审核

系统按稳定指纹去重自然人，并按“候选人—岗位”保存独立状态。候选人详情应包含：

- BOSS 卡片原始字段和采集证据。
- 当前规则版本和规则结论。
- 简历预览/OCR 状态。
- TEM8 或当前英语级别。
- 每个规则叶子的证据、置信度和原因码。
- 语义条件的规范化事实、证据、模型/提示词/语义目录/评分标准版本。
- 审核历史和联系状态。

HR 可以审核通过或拒绝，提交备注和纠错类型。审核采用预期版本号防止并发覆盖。

## 7. 联系

当前产品流程是：审核通过 → 预览消息 → HR 创建联系意图 → Fake Worker 记录 `simulated`。

当前 Dashboard 联系意图固定 `transport_mode=fake`；API 返回 `realGreetingEnabled=false`。内网部署不包含 Real Worker。

产品级自动联系上线前必须补齐：

- 可操作的全局、岗位和任务开关。
- 权限与审批人。
- 权威的 BOSS 账号健康状态。
- 回复同步和 Do-Not-Contact 实时闭环。
- Real Worker 专项验收和紧急停止演练。

## 8. 页面范围

| 页面 | 当前职责 |
|---|---|
| 工作台 | 候选人数、规则通过、待审核、联系数和最新任务 |
| 岗位与规则 | 新建岗位、查看当前规则、编辑并创建新规则版本 |
| 任务与计划 | 立即执行、创建计划、查看任务和停用计划 |
| 候选人审核 | 按岗位查看待审核/已通过/已筛除，查看证据并审核 |
| 联系执行 | 预览消息、创建 Fake 联系意图、查看结果 |
| 审计与安全 | 查看关键动作和当前安全边界 |

## 9. 非功能要求

- 外部操作只能由 Worker 执行，浏览器不得直接调用 BOSS。
- 任务、审核、联系和计划必须幂等并保留审计。
- 已发布规则版本不可原地修改。
- 简历预览开关与联系开关必须独立。
- 单个候选人失败不能丢失已完成结果。
- 大模型不可覆盖 BOSS 平台标签，不得在缺少原文证据时给出确定结论。
- 模型输出必须经过 Schema 校验；模型、提示词、评分标准和语义目录均需版本化并支持历史回放。
- 不从简历推断岗位无关的敏感个人属性；模型输入、输出和凭据不得离开批准的内网边界。
- 所有日期按 UTC 存储，计划业务时区当前固定为 `Asia/Shanghai`。
- 当前只部署在内网，不包含公网域名、TLS、CDN、WAF 或公网数据库方案。

## 10. 当前验收口径

当前阶段通过标准：

- 岗位、规则、立即任务和定时计划可以通过 Dashboard 创建。
- 推荐/搜索结果可去重入库并进入简历精筛队列。
- 规则证据、TEM8 和当前英语级别可查看。
- HR 审核、消息预览、Fake 联系和审计闭环可重复执行。
- 自动化测试与 E2E 明确断言没有真实打招呼。

通用语义筛选的代码链路属于当前已通过范围；真实模型效果、批量回放与评估集尚未通过。多部门权限、招聘管道、面试、Offer、自动联系和分析不属于当前已通过范围。
