## 本轮发现与修复

1. 空白/不完整简历截图失败会刷新整个 BOSS 页面，替换尚有排队候选人的推荐池。现改为关闭简历弹层、保留推荐列表，由既有任务重试机制继续处理。
2. 按岗位 ID 读取推荐的新增路径没有覆盖 iframe 被替换的异常。现仅对读取/恢复推荐上下文做最多 3 次重试，每次重新获取页面框架；岗位不匹配等业务错误仍直接返回，不重复候选人简历点击。

新增回归执行安装后的真实 `runPreview` 失败分支，验证初始内容不就绪与截图失败均只打开一次、关闭弹层、不调用 reload；同时覆盖实际 detached Frame 错误、重新读取、非暂态错误与重试次数上限。96 个文件、637 项测试及 TypeScript 检查通过；Linux amd64 离线安装新补丁与同批测试通过。

`recommend-stability-20260907-1625cst` 已部署；新镜像内确认 `preview` 不再含 `page.reload`。实际连续读取同一岗位两次，均为 15 人且 locator 摘要均为 `3f5bb62b581e17c8`。通过正常 API 重试原批次 6 条异常：1 份恢复并完成 OCR、精筛；其余 5 份仍不在当前推荐池。最终为 **10 份精筛成功、5 份来源暂不可见**，0 条联系意图，任务进入等待审核，队列结束。没有把旧来源失效伪装成修复成功。

前端追加结果说明：直接区分“未满足的条件”和“待核实的信息”，并解释按缺失即不通过处理的规则；详情将技术字段 bossPlatformTags 显示为“BOSS 院校标签”。增加两项判定说明回归，最终 96 个文件、639 项测试、类型/lint 检查及 Linux 生产构建通过。

后台自动刷新实测：同一页面从 9/15 更新到 10/15，无新增文档加载；异常数与重试时间同时显示。候选人列表按“已成功精筛”“仍在处理”“精筛异常”区分，未把失败读取算作规则淘汰。

发布复验发现预构建产物被默认 `.dockerignore` 的 `**/dist` 排除，旧前端仍留在基础镜像。最终 `feature-verified-20260907-1640cst` 使用专用产物 ignore 文件，确认新镜像中的服务入口和资源清单与已测试的 Linux 构建 SHA-256 一致。该问题与相应发布检查已补入部署文档。
