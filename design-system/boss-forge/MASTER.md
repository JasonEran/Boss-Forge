## 1. 产品界面原则

Boss-Forge 是高密度招聘运营 Dashboard，不是营销落地页。设计优先级依次为：任务连贯、状态可读、证据可核对、键盘可用、响应式。

- 使用清晰分区和紧凑表格，不使用大面积 Hero。
- 高风险操作必须在 Dialog 中显示目标和后果。
- 筛选条件必须可见，不把关键过滤器藏入二级菜单。
- 状态同时使用文字和颜色，不能只依赖颜色。
- 外部副作用按钮必须准确写“预览”“打招呼”“发送消息”等实际行为；模拟状态不得冒充真实送达。

## 2. 技术基础

- Tailwind CSS 4。
- shadcn 组件与 Base UI primitives。
- Lucide React 图标。
- Vinext/React 19。
- 不加载 Google Fonts；使用系统字体栈。

字体：

```css
--font-sans-ui: Inter, 'PingFang SC', 'Microsoft YaHei', system-ui, sans-serif;
--font-mono-ui: 'SFMono-Regular', Consolas, 'Liberation Mono', monospace;
```

## 4. 页面结构

所有页面共享：

- 64px sticky Header。
- 桌面左侧导航，移动端顶部横向导航。
- 页面标题、说明、岗位选择和主要动作。
- 内容区使用 Card、Table、Tabs、Badge 和 Dialog。
- `body` 最小宽度 320px。

主导航为 9 个角色化模块：工作台、岗位设置、任务与计划、候选人、联系、实时沟通、招聘流程、招聘运营、系统设置。招聘流程紧接实时沟通。岗位信息、规则编辑、当前生效版本和待发布状态必须集中在岗位设置页，不再显示筛选规则或识别治理 Tab；旧 URL 仅作兼容跳转。任务、候选人、联系、实时沟通和招聘流程不再显示重复的页内导航；联系安全设置归入系统设置。数据分析和审计继续使用所属模块的 Tab。新增页面前先判断是否应成为现有模块的 Tab 或 Dialog。

## 5. 组件规范

### 5.1 Button

- 主动作每个区域最多一个 primary。
- 次要动作使用 outline/secondary。
- 图标来自 Lucide，图标和文字同时存在时保持统一间距。
- 异步提交期间 disabled，并显示 Loader。
- 真实副作用不得只用模糊的“确认”文案；展示账号、岗位、对象和实际动作。

### 5.2 Card 与 Table

- 指标用 Card；批量候选人、任务和审计用 Table。
- 卡片默认白底、细边框和轻阴影，不使用大幅悬浮位移。
- 表格行需要明确的状态 Badge 和可点击目标。
- 超过 25 个候选人显示分页；服务端分页与总数保持一致。

### 5.3 Form

- Label 与输入字段保持可访问关联。
- 必填、默认值、单位和缺失策略必须可见。
- 规则表单保存的是新版本，按钮应写“保存新版本”或等价文案。
- 多值关键词用逗号/换行约定时必须提供示例。
- 验证错误显示在 Dialog 内，并保留用户输入。

### 5.4 Dialog

- 用于新建岗位/规则、计划、审核和消息预览。
- 标题描述对象和动作，正文展示不可逆影响。
- 长表单可滚动，底部动作保持可发现。
- 关闭不应静默提交。

### 5.5 Badge

- 成功：符合、已通过、已精筛、模拟完成。
- 警告：歧义、信息不足、待审核、等待处理。
- 破坏性：失败、拒绝、不符合。
- 中性：未安排、已取消、关闭。

Badge 文案以业务语言为主，不直接显示数据库枚举。

## 6. 交互与动效

- 默认过渡 150–250ms。
- 不使用 GSAP 或滚动揭示；当前应用没有这些依赖。
- Hover 不得改变布局尺寸。
- `prefers-reduced-motion: reduce` 时动画和过渡缩短到近乎即时。
- 轮询刷新不能打断正在编辑的 Dialog 或重置输入。

## 7. 响应式与可访问性

- 验证宽度：320、375、768、1024、1440px。
- 移动端表格可以转换为卡片或受控横向滚动，不能截断主要动作。
- 所有图标按钮有可读名称。
- 键盘焦点使用 `--ring`，不得移除 outline 而不提供替代。
- 正文对比度至少 4.5:1。
- 颜色不是唯一状态提示。
- Sticky Header/导航不能遮住内容或 Dialog。

## 8. 禁止项

- Emoji 代替功能图标。
- 隐藏关键筛选条件。
- 把 Fake 联系写成“已发送”。
- 把未实现的自动联系开关画成可用状态。
- 在前端展示 OCR 密钥、完整环境变量或敏感 stdout。
- 无目标确认的批量审核/联系。
- 低对比度文本、不可见焦点和布局跳动 Hover。

## 9. 交付检查

- [ ] 与当前 7 个一级模块信息架构一致。
- [ ] 桌面和移动导航可用。
- [ ] 所有异步动作有 loading、disabled 和错误状态。
- [ ] 状态文案与数据库行为一致。
- [ ] Fake/Real、预览/发送的边界明确。
- [ ] 320–1440px 无主要内容遮挡。
- [ ] 键盘焦点和 Dialog 焦点管理正常。
- [ ] `prefers-reduced-motion` 生效。
- [ ] `pnpm lint:web`、`pnpm typecheck` 和 `pnpm web:build` 通过。


## 2026-09-05 工作区改版

- 全部模块使用同一个 WorkspaceShell；桌面固定 216px 深蓝侧栏，内容区独立滚动，移动端保留横向导航。Header 使用实体背景，避免 Safari 的 backdrop-filter 点击问题。
- 主色用于下一步操作和选中态。现有联系模式在需要的页面显示；不再占据重复的导航说明面板。
- 岗位与任务组成统一工作上下文，保存在当前用户的会话和 URL 中。任务记录直接链接自己的候选人，跨模块不会默认跳到另一任务。
- 候选人合并为单一名单：待审核、已通过、未通过／淘汰、精筛异常、全部。搜索姓名及卡片信息，按可处理状态排序、每页 20 人。
- 审核弹窗支持队列前后切换、审核后继续下一人、固定操作栏。未提交备注不会带到另一人；异步详情只显示当前候选人的结果。
- 岗位规则编辑扩大至 4xl，保存栏保持可见，所有规则字段和复杂规则配置保留。
- 任务进度按实际已处理简历计算，不再根据状态猜测百分比。定时计划列表完整显示。
